# フロントエンド

React・TypeScriptで、会計担当者がPC1台を操作する画面を実装します。保存済みの記録は`Cashier`ポートから読み、入力中の状態はReactで管理します。

## 画面と主要ファイル

文字サイズは補足12px・本文16px・見出しと金額24pxに揃えます。アイコン操作には表示名とツールチップを付け、金額・返金・札の回収など判断が必要な操作には文字を残します。

| ファイル | 責務 |
|---|---|
| `src/App.tsx` | 起動状態、画面切り替え、下書き、保存中・エラー・復元後の状態、PWA更新 |
| `src/components/Startup.tsx` | 初回準備と営業再開前の確認 |
| `src/components/Checkout.tsx` | 商品・本数入力、未入金の注文、入金確認 |
| `src/components/Waiting.tsx` | 未受け渡し一覧、受け渡しと札回収、完了を元に戻す操作 |
| `src/components/History.tsx` | 営業日・札番号による履歴検索・返金 |
| `src/components/OrderDetails.tsx` | 履歴と返金で共有する会計番号・日時・現金・札の要約 |
| `src/components/Settings.tsx`、`MenuSettings.tsx` | 商品・価格、経費、バックアップなどの設定 |
| `src/components/DataPanel.tsx`、`Recovery.tsx` | バックアップ・復元、結果が未確認の操作の照合 |
| `src/components/controls.tsx`、`src/controls.css` | ボタン・選択欄・開閉欄・ダイアログの共通操作と見た目 |
| `src/presentation/format.ts`、`src/styles.css` | 表示形式と画面のレイアウト |
| `src/ui.ts`、`src/useExclusiveTab.ts` | 画面間の操作型、Web Locksによる二重起動抑止 |

## 依存とデータフロー

```text
入力 → domainで見積もり → Cashierポートへ操作を渡す
     → applicationで検証・保存 → コミット済みSnapshot → 再描画
```

`src/bootstrap.ts`が組み立てた`cashier`を使います。画面から`storage/`やDexieを直接参照しません。金額計算や札の所有条件はdomain/applicationで判断し、UIは結果を表示します。

保存中は重複操作を抑止し、失敗時には保存状態を読み直します。保存結果が分からない操作は`Recovery`で同じ操作IDを照合し、入力し直しや二度目の入金へ誘導しません。

## 入力状態の扱い

- 会計の下書きは`App`で保持し、会計・注文履歴・設定を往復しても消さない。会計画面は非表示にして保持するため、お預かり金額や受け渡し完了行も往復で消えない。金額は注文ごとの入力とし、次の注文へ持ち越さない。
- 最初の商品入力で価格を固定する。設定変更後も入力中の注文には当時の価格を使う。
- 未入金の本数修正は、現金未受領を確認して保留を取り消し、その数量と価格を下書きへ戻す。受領の有無が未確認の入金操作がある場合は先に照合する。
- 設定は画面から隠しても保持し、未保存の編集を画面往復で失わない。未保存の設定があればブラウザを閉じる・再読み込みする前に確認し、アプリ更新を無効にする。再読み込みを選んだ場合に入力を復元する機能はない。
- 商品価格・セット本数・セット価格は`presentation/menu-form.ts`で入力文字列として保持し、保存時に検証して数値へ変換する。空欄と意図した0円を区別する。
- 販売価格の切り替えは保存済みの商品・セットへ適用し、未保存の商品編集は別に保持する。商品編集の保存で現在の販売モードを巻き戻さない。結果は既存の「販売中」表示で通知し、編集欄の位置を動かさない。
- 注文をクリアした後は本数と当時の価格を元に戻せる。新しい本数入力を始めたら、クリアした下書きの復元は終了する。
- 履歴は営業日・札番号・未受け渡しで絞り込み、50件ごとに表示する。

受け渡しの完了行は同じ場所に残し、「完了表示を片づける」で整理します。時間経過で次の札を同じ位置へ移動させません。札で絞り込んだ後も完了した行を保持し、取り消せない場合は理由を示します。

返金確定後は、未回収の札についてその場で回収を記録するか後回しにするか選びます。後回しの札は待ち一覧の札アイコンから確認し、実物を回収した時だけ回収を記録します。札の一覧はダイアログで開くため、注文一覧の高さを圧迫しません。

会計番号は確定済みの入金ログの連番から導出し、保存形式は増やしません。番号に欠番はありますが、同じ札・日時・内容の注文も区別できます。履歴と返金画面は共通の会計情報を使います。

PCの会計パネルは画面の高さに合わせ、商品欄だけをスクロールします。合計と主操作はその外に置きます。設定カテゴリは同じ領域へ重ねて配置し、非表示カテゴリの大きさも確保して切り替え時の位置移動を防ぎます。

## 開始と記録の保存

開始画面は小さなイラストの下に入力・確認欄を置き、縦に読む構成です。日付・価格を確認して会計を始めます。会計件数と使用中の札の枚数は表示しません。直近の記録の一覧や0件の確認待ちは表示しません。途中の会計だけは札と金額を直接表示し、二重入金を防ぎます。

記録の保存・売上一覧・読み込みは短い説明を添えて常時表示します。保存したファイルの再確認と、置き換え前の退避確認は維持します。

PWAの更新は画面へ戻ったとき・再接続時・表示中の定期確認で検出します。検出だけでは再読み込みせず、入力や記録を保ったまま、利用者が更新を実行します。

## UIの変更手順

1. [要件](requirements.md)と[運用手順](operations.md)で、現金・札・入力状態への影響を確認する。
2. `Button`・`IconButton`・`Select`・`Disclosure`・`Dialog`を使う。選択欄は共通のリストボックスで揃え、キーボードとフォーカスを保つ。
3. 日常語で操作を示し、営業日や札枚数は開閉せずに表示する。標準のボタン・入力欄は40px、フォーカス枠は一つにする。
4. 保存前後・画面往復・狭い画面・マウスとキーボードを確認する。保存処理へ影響する場合は[backendの変更手順](backend.md)も確認する。

検証コマンドは[CONTRIBUTING.md](../CONTRIBUTING.md)、自動試験で確認する範囲と実機で残る項目は[検証範囲](acceptance.md)を参照してください。
