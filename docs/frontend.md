# フロントエンド

React・TypeScriptで、会計担当者がPC1台を操作する画面を実装します。保存済みの記録は`Cashier`ポートから読み、入力中の状態はReactで管理します。

## 画面と主要ファイル

文字サイズは補足12px・本文16px・見出しと金額24pxに揃えます。アイコン操作には表示名とツールチップを付け、金額・返金・札の回収など判断が必要な操作には文字を残します。

| ファイル | 責務 |
|---|---|
| `src/App.tsx` | 起動状態、画面切り替え、下書き、保存中・エラー・復元後の状態、PWA更新 |
| `src/components/Startup.tsx` | 初回準備と営業再開前の確認 |
| `src/components/Checkout.tsx` | 商品・本数入力、未入金の注文、入金確認 |
| `src/components/Waiting.tsx` | 未受け渡し一覧、受け渡しと札回収、完了を元に戻す操作 |
| `src/components/History.tsx` | 営業日・札番号・時間帯による履歴検索、並べ替え、CSV出力、返金 |
| `src/components/OrderDetails.tsx` | 履歴と返金で共有する会計番号・日時・現金・札の要約 |
| `src/components/Settings.tsx`、`MenuSettings.tsx` | 商品・価格、バックアップなどの設定 |
| `src/components/DataPanel.tsx`、`Recovery.tsx` | バックアップ・復元、結果が未確認の操作の照合 |
| `src/components/controls.tsx`、`src/controls.css` | ボタン・選択欄・ダイアログ・ダイアログ内のエラー表示・キーの連続入力抑止の共通部品 |
| `src/presentation/` | 金額・日時・会計番号の表示形式、時間帯の選択肢、CSV出力、利用者向けのエラー文 |
| `src/styles.css` | 画面のレイアウト |
| `src/ui.ts` | 画面間で共有する型（操作・下書き・直前の受け渡し）と操作名 |
| `src/hooks/` | Web Locksによる二重起動抑止、アプリ更新の検出と適用、通信状態、未保存時の離脱確認 |

## 依存とデータフロー

```text
入力 → domainで見積もり → Cashierポートへ操作を渡す
     → applicationで検証・保存 → コミット済みSnapshot → 再描画
```

`src/bootstrap.ts`が組み立てた`cashier`を使います。画面から`storage/`やDexieを直接参照しません。金額計算や札の所有条件はdomain/applicationで判断し、UIは結果を表示します。

保存中は重複操作を抑止し、失敗時には保存状態を読み直します。保存結果が分からない操作は`Recovery`で同じ操作IDを照合し、入力し直しや二度目の入金へ誘導しません。

## 入力状態の扱い

- 会計の下書きは`App`で保持し、会計・注文履歴・設定を往復しても消さない。会計画面は非表示にして保持するため、お預かり金額も往復で消えない。金額は注文ごとの入力とし、次の注文へ持ち越さない。
- 最初の商品入力で価格を固定する。設定変更後も入力中の注文には当時の価格を使う。
- 未入金の本数修正は、現金未受領を確認して保留を取り消し、その数量と価格を下書きへ戻す。受領の有無が未確認の入金操作がある場合は先に照合する。
- 設定は画面から隠しても保持し、未保存の編集を画面往復で失わない。未保存の設定があればブラウザを閉じる・再読み込みする前に確認し、アプリ更新を無効にする。再読み込みを選んだ場合に入力を復元する機能はない。
- 商品価格・セット本数・セット価格は`presentation/menu-form.ts`で入力文字列として保持し、保存時に検証して数値へ変換する。空欄と意図した0円を区別する。
- 販売価格の切り替えは保存済みの商品・セットへ適用し、未保存の商品編集は別に保持する。商品編集の保存で現在の販売モードを巻き戻さない。選択中の価格ボタンで販売モードを示し、重複する状態説明は表示しない。
- 注文をクリアした後は本数と当時の価格を元に戻せる。新しい本数入力を始めたら、クリアした下書きの復元は終了する。
- 履歴は営業日・札番号・状態・日本時間の時間帯で絞り込み、時刻・札番号・会計額の順に並べ替えてから50件ごとに表示する。初期表示は現在の営業日。時間帯は営業時間10:00〜17:00の30分単位の選択とし、開始時刻を含み終了時刻は含めない（10:00–10:30なら10:00から10:29まで）。営業時間外の注文は「すべての時間」で確認する。営業時間と時間帯の長さは`src/domain/constants.ts`で定め、集計の30分ごとのグラフと共有する。表の見出しで昇順・降順を切り替える。

受け渡しと札回収の保存が成功したら、完了行を待ち一覧からすぐ外します。二重クリックとキーのリピートを抑止し、500ms以内の連続完了も拒否します。「元に戻す」は残し、取り消せない場合は理由を示します。

返金確定後は、未回収の札についてその場で回収を記録するか後回しにするか選びます。後回しの札は待ち一覧の札アイコンから確認し、実物を回収した時だけ回収を記録します。札の一覧はダイアログで開くため、注文一覧の高さを圧迫しません。

会計番号は確定済みの入金ログの連番から導出し、保存形式は増やしません。番号に欠番はありますが、同じ札・日時・内容の注文も区別できます。履歴と返金画面は共通の会計情報を使います。

PCの会計パネルは画面の高さに合わせ、商品欄だけをスクロールします。合計と主操作はその外に置きます。設定内のタブは使わず、商品・価格、バックアップ、日付・番号札、記録の保護を縦に並べます。

## 開始と記録の保存

開始画面はパネルと同じ幅のイラストの下に入力・確認欄を置き、縦に読む構成です。日付・価格を確認して会計を始めます。会計件数と使用中の札の枚数は表示しません。直近の記録の一覧や0件の確認待ちは表示しません。途中の会計だけは札と金額を直接表示し、二重入金を防ぎます。

設定では「バックアップを保存」「バックアップから復元」を常時表示します。CSVは注文履歴のダウンロードアイコンへ集約し、表示条件と並べ替えを反映した全ページ分の注文を保存します。バックアップは営業日の `yyyy-mm-dd-yakitori.json` で出力します。再選択する検証欄は設けません。復元はファイル選択・表での内容確認・「この内容で再開」で行い、新しい開催回もバックアップ保存を必須にしません。

PWAの更新は画面へ戻ったとき・再接続時・表示中の定期確認で検出します。検出だけでは再読み込みせず、入力や記録を保ったまま、利用者が更新を実行します。更新にバックアップファイルの再選択・復元は要求しません。入力中・保存中・未確定の会計や操作、未保存の設定・経費があれば更新を止めます。保存済みの記録はIndexedDBに残ります。

## UIの変更手順

1. [要件](requirements.md)と[運用手順](operations.md)で、現金・札・入力状態への影響を確認する。
2. `Button`・`IconButton`・`Select`・`Disclosure`・`Dialog`を使う。選択欄は共通のリストボックスで揃え、キーボードとフォーカスを保つ。
3. 日常語で操作を示し、営業日や札枚数は開閉せずに表示する。標準のボタン・入力欄は40px、フォーカス枠は一つにする。
4. 保存前後・画面往復・狭い画面・マウスとキーボードを確認する。保存処理へ影響する場合は[backendの変更手順](backend.md)も確認する。

検証コマンドは[CONTRIBUTING.md](../CONTRIBUTING.md)、自動試験で確認する範囲と実機で残る項目は[検証範囲](acceptance.md)を参照してください。

## 注釈で指摘された配置の整理（2026-11-01）

- 注文見出しの装飾アイコンと通知専用の空行を削除。通知と取り消しは見出し横へ置き、商品・会計ボタンの位置を保つ。
- 商品名・価格・数量操作を分け、価格の右端を縦に揃える。
- 履歴の日付・時間帯・札番号・状態を横一列へ置く。狭い画面では折り返す。会計番号は左端の列とし、表の見出しと内容を16pxで揃える。
- 日付と札枚数は一つのフォームで編集し、変更がある時だけ共通の「保存」を表示する。既存の保存操作を札枚数、日付の順に実行する。途中で失敗した場合は保存済み状態を再取得し、残りの編集を保持する。
- 読み込みと翌年の準備は同じ幅・高さのボタンで揃える。
- アプリ情報には連絡先と既存のMITライセンスへのリンクを掲載する。
- 空状態のGIFは透過背景でループし、停止ボタンは設けない。動きを減らす設定では静止画に切り替える。両方をオフライン配信対象へ含める。

## 営業後の集計

`Summary.tsx`が日別と全体の売上・会計数・販売本数を表示し、全体の経費を登録する。`domain/sales.ts`の既存計算を使い、返金を差し引いた売上から経費を引く。経費未登録では利益を「—」と表示する。経費の入力は画面を往復しても保持し、未保存の間は更新を止め、再読み込み前に確認する。経費は設定から移し、集計の専用画面で扱う。

ヘッダーは年度・早稲田祭・日付を表示する。「何日目か」は推測せず、準備日や日付の訂正を日数に数えない。

受け渡し欄の上部では商品名と未受け渡し本数を大きく表示します。調理済み・包装済みも含む数で、焼き手の作業残数ではありません。別端末との共有は通信環境が未定のため導入せず、このPC内の表示を改善します。注文詳細は商品を行ごとに並べ、会計額・お預かり・お釣り、受け渡しと札の状態を分けます。セット内訳は合計本数の横に置き、幅が足りないときだけ折り返します。

### 支払い操作

お預かり金額のボタンは「ちょうど・500・1,000・2,000・5,000・10,000円」で固定し、不足額のボタンは位置を変えず無効にします。未入金の取消と入金額の修正は確認ダイアログを挟まず実行し、保存済みの注文・操作の状態遷移は維持します。主操作と「戻る・取消・入金額を修正」は区切り線と余白で離します。

### 集計グラフと表示の統一

`SalesCharts.tsx`は日付を選び、`domain/sales.ts`の30分ごとの売上と商品別販売本数を表示します。時刻は日本時間の会計確定時刻を使い、最初から最後の会計までの売上0円の区間も表示します。商品が5種類以上なら上位3種類とその他に分け、その他の本数も併記します。

支払い確認は「お預かり・− お会計・お釣り」の順で金額の右端を揃えます。札は`Ticket.tsx`を会計・待ち一覧で共用します。履歴の文字は左揃え、金額は右揃えとし、詳細と返金の列位置を固定します。状態は「未完了・完了・取消」の3種類で、未完了は入金前と受け渡し前を含みます。元の会計状態・取消理由は詳細で確認できます。
