# フロントエンド

表示と入力にはReact・TypeScriptを使い、操作は`Cashier`ポートへ渡します。画面からDexie・IndexedDBを直接操作しません。業務ルールは[backend](backend.md)、利用者向けの概要は[README](../README.md)を参照してください。

## 画面と責務

## 遷移と入力状態

ホームから「営業を準備」（初回）・「新しい営業を作る」・「会計を始める」・「営業後の集計」へ進みます。営業名の横にある鉛筆アイコンから、その日だけの名前を変更できます。会計中の中央ナビゲーションはホーム・会計・注文履歴・設定です。ロゴもホームへ戻ります。集計のナビゲーションには、ホームへ戻る操作だけを表示します。

会計を初めて開くと、保存されている途中の会計を再開対象にします。同じセッション内でホームを往復しても、会計コンポーネントはアンマウントせず、本数・お預かり金額を保持します。

設定と集計の未保存入力も、画面を非表示にしたまま保持します。画面を離れるときは確認を出し、ホームから営業日を変更・復元する場合も、非表示の画面にある未保存の編集内容を保護します。

復元でDB識別子・復元世代が変わったら、入力をリセットします。同じ日の復元でも古い経費が残らないよう、集計コンポーネントのキーにもDB識別子と世代を使います。営業終了時は保存確認後に入力状態を破棄し、記録を残してホームへ戻ります。

`useDraft`は、本数と固定した価格の下書きを同じDB・世代・営業日に限って一時復元します。すでに注文として保存された下書きを二重に復元しません。未保存設定や経費には再読み込み後の復元を設けません。入力中・途中会計・未保存設定や経費は再読み込み・離脱前に確認します。

## 会計と札回収

最初の本数入力で価格版を固定します。通常価格・値下げ価格の切り替えや商品削除で、入力中・過去の注文を再計算しません。未入金の会計で「戻る」を押すと、取消履歴を残して当時の数量と価格を下書きへ戻します。

お預かり金額には、ボタンで＋100・＋500・＋1,000・＋5,000・＋10,000を加算できます。空欄を0として扱い、「ちょうど」と手入力も使えます。上限超過や不正な手入力を加算で上書きしません。不足金額の表示が変わっても、ボタン位置は変えません。

主操作は「会計へ」→「お釣りを確認」→「会計を確定」→札ダイアログの「この札で確定」です。Enterも各段階で一度ずつ処理し、長押し・連打・保存中の二重実行を防ぎます。`useCheckoutKeys`は1〜9キーで商品を増やし、入力欄・ダイアログ・別画面では無効にします。

札は空いている最小番号を仮確保し、確定ボタンで開くダイアログから変更できます。ダイアログを閉じるかEscapeを押すと、未確定のまま戻ります。保存失敗でも選んだ札・金額・再試行の操作IDを保持します。札表示は`Ticket.tsx`を会計・待ち一覧・詳細で共用します。

待ち一覧には未回収の通常注文を表示し、上部に商品別の未受け渡し本数をまとめます。チェックで受け渡しと実物札の回収を一括保存し、成功後に行を外します。二度押しで次の札を回収しないよう、直後の連続操作を抑止し、次の操作位置も保護します。回収取消は下部の固定枠へ置き、平均待ちの位置を動かしません。札再利用後の取消は理由を表示して拒否します。

平均待ちは`domain/wait-time.ts`から当日直近10件の実績を取得します。札ごとの経過時間は会計確定から数え、30秒ごとに更新します。予測待ち時間としては扱いません。返金済みで未回収の札は別の札アイコンから回収を記録します。

## 履歴と設定

履歴は当日だけを対象に、札番号・状態・時間帯で絞り込み、時刻・金額で並べ替えて50件ごとに表示します。会計番号は左端に置き、札番号での並べ替えや日付選択は設けません。時間帯は日本時間10:00〜17:00の30分単位で、開始時刻を含み、終了時刻を含みません。

行にポインターを重ねると黄色で示し、クリックで詳細を開きます。会計番号もキーボードで選択できます。返金ボタンは詳細を同時に開かず、ダイアログを閉じると操作元へフォーカスを戻します。表の文字は16px、文字列は左・金額は右揃えです。返金ボタンの幅は文字が収まるよう確保します。

設定はタブ・トグルを使わず、商品・価格・在庫、バックアップ、番号札、記録の保護を縦に並べます。セット対象のチェックを商品名の横へ置き、セット条件は`BundleFields`で共用します。商品追加と保存は固定位置のツールバーへ置きます。価格モードは保存済みの設定にだけ適用し、未保存の商品を消したり、保存操作なしで保存したりしません。

`DigitsInput`を札番号検索・札枚数・商品価格・在庫・セット・経費に使います。文字・符号・小数・指数を拒否し、全角数字は半角に変換します。空欄を編集状態として保持し、必須と上下限は送信時に検証します。現金入力は専用の処理を維持します。

## 出力・終了・集計

ホーム・設定のバックアップ保存はJSONだけです。履歴のダウンロードは表示条件・並び順に合う全ページ分のCSVで、ツールチップを「注文履歴（.csv）を保存」とします。ファイル名は`yyyy-mm-dd-yakitori.json`または`.csv`です。

営業終了では同じ最新Snapshotから当日JSONと全件CSVを生成します。「1日、お疲れさまでした！」に本日の販売本数・売上を示し、2ファイルの出力後に保存確認を受け付けます。終了直前にもDB・世代・営業日・連番・未解決作業・未回収札を再確認します。バックアップ履歴は利用者の保存確認を記録するもので、ブラウザから物理保存完了を自動判定しません。

集計は初回に開くまで遅延読込し、その後は非表示で保持します。当日分、または読み込んだ日別JSONの読み取り専用の集計を表示します。経費が未登録なら利益は「—」とし、0円は登録済みとして扱います。30分ごとの売上棒グラフと商品別販売本数の円グラフを表示します。返金は元の会計時刻の売上から差し引き、営業時間外の会計もグラフの範囲に含めます。5商品以上の円グラフは上位3種類とその他にまとめます。

## 再計算の範囲

`Checkout`はSnapshotが変わったときに在庫を一度だけ集計します。`Waiting`は未受け渡し注文から商品別本数を一度にまとめ、Snapshotが変わらなければ結果を再利用します。`MenuSettings`も在庫履歴の集計結果を再利用し、入力のたびに履歴を集計し直しません。履歴の詳細ダイアログを開閉しても、Snapshotと検索条件が同じなら絞り込み・並べ替えを繰り返しません。

## 更新・容量・見た目

接続表示のツールチップには、オンライン／オフラインの状態と、記録はこのPC内に保存され端末間では同期しないことを記載します。接続表示を保存済みや同期済みの意味に使いません。

PWAの更新は、画面への復帰時・再接続時・画面を表示している間の60秒ごとの確認で検出します。検出だけでは再読み込みせず、入力中・保存中・途中会計・未解決操作・未保存編集がない状態で利用者が更新します。記録はIndexedDBへ残し、バックアップの再選択を求めません。

保存容量の概算は、起動時・フォーカス復帰時・60秒ごとに取得します。使用量が保存上限の90%以上で警告しますが、入力・未保存編集・保存中やホームの表示中は待機します。一度通知した不足状態では警告を繰り返さず、85%未満へ回復したら再び通知できる状態に戻します。容量を取得できない環境では誤警告しません。

文字サイズは12px・16px・24px、基本色は紙・墨・黄色、赤はエラー・返金・在庫不足に使います。標準操作は40px、フォーカス枠は一つです。PCの会計欄は商品部だけスクロールさせ、合計と主操作を固定します。901px以上のホームはイラストと操作欄を横に並べ、狭い画面は縦にします。素材は末尾の一覧を参照してください。

試験のコマンドは[CONTRIBUTING](../CONTRIBUTING.md)、自動試験と本番実機で残る確認は[要件の受入条件](requirements.md#受入条件)を参照してください。

## 利用手順と復旧

1. 初回は営業名・日付・商品・価格・札枚数・任意在庫を登録する。翌日は「新しい営業を作る」で別の日付と営業名を登録する。保存済みの日は同じダイアログから再開する。
2. 本数を選び「会計へ」→預かり金を入力し「お釣りを確認」→現金を確認して「会計を確定」→渡す札を確認し「この札で確定」。保存成功後に札を渡す。
3. 商品を渡して実物の札を回収したら、右側のチェックを押す。回収取消は札が再利用される前だけ使う。
4. 未入金の本数修正は「戻る」、金額修正は「入金額を修正」。入金後は履歴の「全額返金」で理由と準備を保存し、現金返却後に記録する。返品で在庫は自動復活しない。
5. 閉店前に途中会計・未回収札・未保存編集を解消し「今日の営業を終了」。本日の本数と売上を確認して「JSON・CSVを保存」、両ファイルの保存を確認して終了する。
6. 保存結果が不明なら新しい注文として入力せず、現金・札と照合して同じ操作を再試行する。復元はJSONを選び、営業名・日付・件数を確認して「この内容で再開」。CSVでは復元しない。

「？」を押すと、READMEの「使い方」を直接読み込む`ReadmeGuide`を表示します。開発者向けの章は表示しません。画面画像も`docs/images`と共有し、説明をコピーした別ファイルは作りません。画像・見出し・段落は安全なReact要素として表示し、HTMLは挿入しません。説明を変更したら、READMEとアプリ内表示の両方を確認してください。
