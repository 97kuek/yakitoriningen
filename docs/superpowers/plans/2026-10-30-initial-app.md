# 初期版の実装計画

**Goal:** 既存の設計に沿う、PC1台で動くオフライン会計アプリを実装する。
**Spec:** `docs/requirements.md`、`docs/architecture.md`
**Architecture:** Reactの画面、純粋な価格計算、Dexieの保存コマンドを分離する。操作の保留・結果、注文、札、設定、連番ログは同一トランザクションで更新する。
**Tech Stack:** React / TypeScript / Vite / Dexie / Zod / Vitest / Playwright

## 制約と実装判断

- 既存の未コミット設計変更を保持。コミット・push・公開は行わない。
- 既存設計を実装する依頼として、この作業場所で実装を進める。
- 金額・数量は安全な整数。外部API・フォント・クラウド同期なし。
- 全更新はDB識別子と世代を検証。同じ操作IDで異なる入力を拒否。
- 部分返金・紙入力・利益・汎用商品編集は未確定のため対象外。未入金取消と全額取消を用意する。
- UIは白、紺（#16324f）、朱赤（#b52f27）、青灰（#eaf0f5）、緑（#1c654a）。システムの日本語フォントを使用。会計を左、札番号が大きな待ち一覧を右に配置し、屋外で読めるコントラストと操作サイズにする。

## Review Focus

1. 満札・二重起動でも重複割当なし。
2. DBコミット後の表示消失でも同じ操作を照合できる。
3. 不正なJSON・価格・金額をDBへ通さない。
4. 復元中断は旧状態を保持。復元前の画面と操作は拒否。
5. 価格変更・日付変更・受け渡しが入力中の会計を変更しない。
