# 焼き鳥人間：担当者の作業を想定したUI・UX確認

確認日：2026-10-31。対象：https://yakitoriningen.pages.dev

マウスとキーボードで操作し、商品を渡す際に番号札も回収する担当者を想定した。専用ブラウザの架空データで、営業開始、注文、会計、金額訂正、受け渡し、札の再利用、混雑、値下げ、注文クリア、履歴、返金対象の確認を実際に操作した。既存の営業データは操作していない。本資料は担当者役としての確認であり、実際の利用者による試用結果ではない。

## 作業に必要な情報

| 作業 | 担当者がすぐ判断したいこと | 画面の役割 |
|---|---|---|
| 営業開始 | 今日の日付・販売価格は正しいか | 確認事項と開始ボタンをまとめる |
| 注文 | 種類と本数が合っているか | 商品・本数・合計を近くに置く |
| 会計 | いくら受け取り、いくら返すか | 請求額→預かり→お釣り→確定の順を保つ |
| 受け渡し | どの札の商品を渡したか | 札と内容を確認して、一度の操作で一件だけ完了する |
| 訂正・返金 | 対象は合っているか、何が確定済みか | 注文の詳細と、戻せる範囲を明示する |
| 終了 | 売上・経費・利益、記録の保存 | 集計確認と保存の入口をまとめる |

## 優先順の指摘

### 1. 最優先：受け渡しの二度押しで、別の注文まで完了する

**実測した不具合。** 待ち注文を3件作り、先頭の完了アイコンを150ms間隔で二度押すと、待ち件数が3件から1件になった。札1の行が消えた位置へ札2が繰り上がり、二度目のクリックが札2へ届く。表示される「元に戻す」も札2の分になった。

- 影響：渡していない注文が一覧から消え、未回収の札が空きとして再利用され得る。
- 改善：操作した行を完了表示へ切り替えて一旦その位置に残し、次の注文の操作が同じクリック位置へ直ちに移らないようにする。画面全体の連続クリック保護も組み合わせて検証する。毎回の確認ダイアログは増やさない。
- 合格条件：マウスの二度押し、Enterの連続入力でも一件だけ完了し、対象の札・内容を確認して戻せる。
- 対象：`src/components/Waiting.tsx:133`、`:167`。
- 証拠：`05-before-double-click.png`、`06-after-double-click.png`、`observations.json`。

### 2. 優先：履歴から返金する注文を区別しにくい

**実際に同じ見た目の2行を再現。** 同じ札1を再利用し、同じ分に「もも1本・150円」を2回会計した。預かり金は1,000円と500円だったが、履歴の日時・札・内容・会計額・状態は同一表示になった。返金画面にも、会計時刻や預かり金・お釣りがない。

- 改善：行を開くと会計日時、預かり金、お釣り、受け渡し状態を確認できるようにする。返金画面にも同じ要約を出す。内部IDを並べず、必要ならその日通しの会計番号を業務上の識別として検討する。時刻の秒表示だけに依存しない。
- 合格条件：同じ札・内容・金額の複数注文から対象を照合でき、選んだ会計の情報を見たまま返金へ進める。
- 対象：`src/components/History.tsx:168`、`src/components/RefundDialog.tsx:82`。
- 証拠：`13-reused-ticket-history.png`、`12-refund-detail.png`。

### 3. 優先：会計ボタンが低い画面で切れる

**画面サイズによる再現。** 1280×640px、ページ先頭で注文を1本入力した際、「会計へ」の上端が632.6px、下端が672.6pxになった。スクロールが必要。1366×768pxでは表示できた。開始ボタンも高さ640pxでは画面外だった。

- 改善：画面の高さに合わせて商品欄の余白を縮め、注文パネルの合計と会計ボタンは常に確認できる配置にする。商品が増える場合は商品一覧をスクロール対象にする。固定フッターが内容やキーボードフォーカスを覆わないことを確認する。
- 合格条件：1280×640pxでも請求額と主操作が画面内にあり、注文数の増減でボタン位置が移動しない。
- 対象：`src/styles.css:30`、`src/components/Checkout.tsx`。
- 証拠：`14-short-screen.png`、`short-screen.json`。

### 4. 優先：値下げの選択と、適用済みの状態が紛らわしい

**操作で確認したUX上の問題。** 設定で「値下げ価格」を選んで会計へ戻ると150円のままだった。設定に戻ると選択状態は維持されているが未保存。高さ768pxでは保存ボタンが最初の画面下端より下にあった。保存後も入力済みの注文は150円を保ち、「50円に変更」で明示的に切り替える仕様だった。

- 改善：日常的な「販売価格の切り替え」を商品マスタの編集から分け、現在の価格と「次の注文から適用」を同じ場所に表示する。設定編集には未保存の表示を出す。注文中の価格を勝手に変更しない契約は保つ。
- 合格条件：現在販売中の価格・未保存の設定・入力中の注文価格を混同せず判断できる。
- 対象：`src/components/MenuSettings.tsx:215`、`:236`、`src/components/Checkout.tsx:137`。
- 証拠：`09-unsaved-discount.png`、`10-price-frozen.png`。

### 5. 次点：間違えたときに戻せない、理由が分からない

- 注文のリセットアイコンは即時に本数を0にする。「注文を消しました／元に戻す」を同じ場所へ出すと再入力を減らせる。確認ダイアログを毎回挟む必要はない。`src/components/Checkout.tsx:106`。
- 札を再利用すると受け渡しの「元に戻す」が無効になるが、その理由が表示されない。「この札は次の注文で使用中のため戻せません」など、実際の再利用履歴に合う説明を出す。安全上の禁止は維持する。`src/components/Waiting.tsx:81`。
- 預かり金の訂正ではブラウザ標準の確認が現れ、「現金を照合」「会計未確定」という文を読む必要がある。共通ダイアログへ統一し、「受け取ったお金とお釣りを確認してから、金額を入力し直してください」など、現金の扱いを具体的に示す。保存済みの準備を破棄する確認は維持する。`src/components/Checkout.tsx:458`。

### 6. 次点：混雑時に探せる注文が少ない

1366×768pxで12件の待ち注文を作ると、一覧の高さは350px、内容は983pxで、完全に見える行は4件だった。合計本数・完了メッセージ・余白が一覧の上にある。札を大きくする必要はない。

- 改善：待ち件数が増えたら補助情報の余白を縮め、札・商品・完了アイコンの行を優先する。必要に応じて札番号で絞り込める入口を検討する。件数と空き札数は残す。
- 合格条件：12件以上でも探している札へ素早く到達でき、スクロール中や完了後に別の札を操作しない。
- 証拠：`08-peak-queue.png`。

## 残したい挙動

- 注文と受け渡しが左右にあり、会計中も待ち注文を見られる。
- もも2・かわ2・ねぎま1でセット600円、1,000円預かりでお釣り400円になった。
- 会計前の本数修正、預かり金の修正が可能。
- 価格変更で入力中・会計済みの注文を勝手に変えない。
- 受け渡しと札回収を一操作にまとめる。確認が必要な会計・返金の文字は残す。
- 基本色とアイコンの大きさは維持し、状態の説明が必要な箇所へ短い文字を使う。

## 修正のまとまり

1. 受け渡しの二度押し防止と取り消しの説明。
2. 注文詳細と返金対象の照合。
3. 高さに対応した会計・待ち注文の配置。
4. 販売価格の切り替えと未保存表示、注文クリアの復元、訂正ダイアログの統一。

変更後は同じシナリオを再実行する。その後、実際の担当者へ「混合5本を会計」「預かり金を訂正」「混雑中に札を探して渡す」「値下げ」「同じ札の履歴から返金」の課題を渡し、説明なしで進められるかを確認する。担当者による所要時間・迷い・誤操作は今回未測定。

補助的な確認観点：[Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)。優先順位は、今回実際に確認した現金・札・操作位置への影響に基づく。
