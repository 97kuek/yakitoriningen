# 営業日・復元・在庫調整・経過時間

依頼された4点を既存のCashierポート、営業日別ログ、共通フォームに沿って実装する。

1. 設定の日付直接編集を外し、新規日は既存の営業準備フォームに集約する。保存済みの日へ戻る場合も同じ入口で選び、途中の会計・未回収札がある切り替えは拒否する。商品・在庫・札枚数を再開先の設定へ合わせる。
2. 復元はバックアップに含まれる営業日の記録を対象とし、他の日を保持する。プレビュー後の変更検知、一括書き込み、世代変更を保つ。会計番号の衝突や他の日の未解決操作は削除せずエラーにする。旧複数日バックアップも受け付ける。
3. 登録済み商品の在庫は「追加」「廃棄」の数量で調整する。差分を業務ログに保存し、追加で残数を増やし、廃棄は会計中の予約分を下回らない。任意の初期在庫入力と商品・価格との共通保存は維持する。
4. 各札に会計確定からの経過分数を表示する。平均実績とは区別し、会計未確定の予約を待ち時間に含めない。表示を定期更新し、長押し・札再利用の保護を維持する。

## 検証

- 復元で別日の注文・在庫・経費・会計番号が保持されること、衝突とプレビュー後変更で全体が変更されないことを実DB相当の試験で確認する。
- 新規日準備／既存日再開、在庫追加20本・廃棄3本・予約分未満の拒否、経過時間の更新を試験する。
- 型・単体・書式・ビルド・全ブラウザ試験と実画面確認後、依存方向・命名をレビューする。
- 業務処理、画面、ドキュメントを論理単位でコミットしmainへpush、自動デプロイを確認する。
