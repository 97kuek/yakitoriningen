# 要件定義書

更新日：2026-10-31

本書は「焼き鳥人間」の機能と運用条件を定めます。実装の構成は[全体アーキテクチャ](architecture.md)、自動試験と未検証項目は[検証範囲](acceptance.md)を参照してください。

## 1. 目的と利用条件

WASAの早稲田祭出店で、注文受付・現金会計・注文確認・受け渡しをPC1台で行います。開発者が当日いなくても担当者が操作でき、翌年も引き継げることを目指します。

早稲田祭は年1回、2日間開催します。同じ開催回で2日分の記録と経費を管理し、翌年は前年の記録を保存ファイルで保管し、新しい開催回として準備します。商品・価格と札の枚数を引き継ぎ、値下げは解除します。日付の決定は現場で行い、年ごとの開催日を固定しません。

| 項目 | 条件 |
|---|---|
| 利用端末 | PC1台・会計画面1つ。会計と受け渡しの2人体制を想定 |
| 初回準備 | 営業前にオンラインでアプリを取得し、オフライン起動と保存を確認 |
| 営業中 | 注文・会計・保存・受け渡し・集計を通信なしで実行 |
| 起動方法 | ブラウザでURLを開くPWA。現場でコマンドやOS別の保存用アプリを用意しない |
| 保存 | 端末のIndexedDB。クラウドDB同期・オンライン認証は使わない |
| 優先事項 | DB記録の確実性。PCの処理速度の優劣は評価対象外 |
| 配布 | Cloudflare Pagesによる静的配信。公開・更新手順は別文書 |
| 対象外 | 複数PCの同時会計、別スマホへの注文送信、部分返金・部分受け渡し、紙からの復旧入力 |

本番のPC・ブラウザ、営業時間、販売予定本数、担当者と配置は運用前に確定します。

## 2. 商品と価格

- 初期商品はもも・かわ・ねぎま。通常価格は各150円、値下げ価格は各50円、通常のセットは組合せ自由の5本600円を初期値とする。
- 商品は最大30種類。商品ごとにID・名前・通常価格・値下げ価格を持ち、画面から追加・削除・変更できる。
- セットは一つのルールとして対象商品群・本数N・価格X円を設定する。対象商品から組合せ自由でN本を選び、適用可能な組合せのうち最安額を使う。単品より高いセットは適用しない。
- 値下げは担当者が手動で切り替え、全商品にそれぞれの値下げ価格をまとめて適用する。値下げ中のセット適用は別に設定し、既定では無効とする。
- 旧形式の種類別セット設定・価格・バックアップを引き続き読み込める。
- 最初の商品入力で価格の版を固定する。価格や商品を変更しても、入力中・会計済みの注文の商品名・数量・当時の価格・合計を変えない。
- たれ・塩だれの希望は受け渡し時などに口頭で確認し、会計画面では選択・記録しない。

値下げは16:00ごろを目安とする案がありますが、自動切り替えは行いません。実施時刻は現場で判断します。

## 3. 画面と業務フロー

会計画面には数量入力と受け渡し待ち一覧を並べ、注文履歴と設定へ切り替えられる構成とします。

1. 開催回・営業日・価格・番号札・保存状態・未解決操作を確認して営業を始める。
2. 商品の本数を入力し、合計とセット内訳を確認する。
3. 「会計へ」で注文と空き札を保留保存する。満札なら現金を受け取らず回収を待つ。
4. お預かり金額と確定操作を保存し、お釣りを確認する。
5. 現金・釣り銭のやりとり後に会計を確定する。保存成功後、待ち一覧へ反映された札を渡す。
6. 商品を渡して札を回収し、完了操作を一度行う。
7. 休憩・閉店時にバックアップを出力し、ファイルと別媒体への退避を確認する。

保留保存だけでは売上に含めません。保存結果が不明なら同じ注文・操作を照合し、別注文としての再入力や二度の入金・返金を求めません。

## 4. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | 商品・数量 | 商品ごとの本数を入力する。未入金なら現金未受領を確認して保留を取り消し、当時の価格と数量を下書きへ戻して修正できる |
| FR-02 | 合計金額 | 商品別単価とセット条件から最安額を計算し、本数・内訳・合計を表示する |
| FR-03 | お釣り | お預かり金額から計算し、不足金額での確定を拒否する |
| FR-04 | 会計確定 | 入金の準備を保存した後に確定し、保存成功後に会計済みと表示する。二重登録を防ぐ |
| FR-05 | 注文確認 | 同じPCの会計画面に未受け渡し注文を表示する |
| FR-06 | 注文表示 | 札番号・商品名・商品ごとの本数を表示する。削除済み商品も当時の名前で示す |
| FR-07 | 受け渡し | 商品受け渡しと札回収を一括保存し、待ち一覧から外す。直前の完了は、札が次の注文に一度も再利用されていなければ元に戻せる |
| FR-08 | 番号札 | 空き札を一つの注文へ割り当て、回収後に再利用する。使用中の重複と古い注文からの札操作を拒否する。札枚数は1〜100で変更できる |
| FR-09 | 商品・価格設定 | 商品の追加・削除・商品別価格・セット条件を設定する。未保存の入力を、設定項目や画面の往復で保持する。未保存時は離脱・再読み込み前に確認し、アプリ更新を止める。再読み込み後の未保存入力の復元は対象外 |
| FR-10 | 注文履歴 | 開催回全体・営業日別の履歴を表示し、札番号検索・未受け渡し絞り込み・50件ごとのページ切り替えに対応する |
| FR-11 | 操作の保護 | 設定・全額返金・復元を会計入力から分け、対象と保存内容を確認できるようにする |
| FR-12 | 開催回・営業日 | 開催回と各注文の営業日を保存する。営業日変更時も未完了の注文・未回収札・開催回の経費を保持する |
| FR-13 | 出力・復元 | 通信なしで復元用JSONと集計用CSVを出力できる。復元時は内容・整合性・現状の退避を確認する |
| FR-14 | 値下げ | 商品別の値下げ価格へ手動でまとめて切り替え、次の注文から使う |
| FR-15 | 経費 | 開催回全体の経費合計を登録し、未登録と0円を区別する。売上・利益の集計画面は設けない |
| FR-16 | 全額返金 | 返金理由と準備を先に保存し、現金確認後に元注文へ関連付けて記録する。売上と販売本数から差し引き、元会計と操作履歴を残す |

未受け渡し本数は調理済み・包装済みも含み、これから焼くべき本数とは区別します。通常の完了は実物の札を回収してから押します。札の紛失・部分受け渡しは現場で別途扱いを決めます。

設定は「商品・価格」「経費」「記録・その他」の3カテゴリに分け、バックアップは「記録・その他」に置きます。営業日・札枚数・記録の保護は開閉せずに表示し、日常語で案内します。

## 5. 保存・集計の契約

### 注文と操作

- 再利用しない注文IDと、再利用する札番号を分ける。札の現在の所有者は注文ID・割り当てIDで検証する。
- 注文・札・操作結果・連番ログを同じトランザクションで記録する。保存完了前に会計済み・札が空いたと表示しない。
- 同じ操作ID・同じ内容の再試行は既存結果を返す。同じIDで異なる内容は拒否する。
- 全更新でDB識別子と復元世代を確認し、復元前の画面・保留からの古い操作を拒否する。
- 完了取り消しも注文・札・操作・ログを一括保存する。札が再利用された後に空きへ戻っていても、過去の完了取り消しは拒否する。
- 取消や取り消しは記録として残す。確定済みの会計・価格履歴・業務ログを通常操作で削除しない。

### 売上と利益

売上は注文に保存した会計額から実際の返金額を差し引きます。販売本数はセットも本数で数え、全額取消した注文は本数からも差し引きます。現在の価格で過去の注文を再計算しません。

利益は「開催回全体の返金差引後の売上 − 開催回全体の経費合計」です。経費は費目別明細ではなく合計額を登録し、増えた場合は合計を更新します。未登録は`null`、登録済み0円は`0`として区別し、経費が未登録なら利益も未登録とします。売上・利益の集計やグラフは画面に表示しません。

## 6. オフラインと復旧

- 同じURL・ブラウザの通常プロファイルを使う。プライベートモードや複数タブでの同時会計は対象外。
- アプリ本体・画像などを事前取得し、営業中に外部API・フォント・CDNを必要としない。
- 初回準備と営業再開を分ける。DBがない状態を自動初期化で隠さず、開催回・営業日・直近の注文・札・未解決操作を確認する。
- 保留や結果未確認の操作は再起動後に照合できる。現金の受領・返金・実物の札を自動推定しない。
- JSONは全ストアの同じ時点の記録を取得する。ダウンロード開始と、ファイル確認・別媒体への退避を区別する。
- 復元時は形式・注文・価格・札・操作・ログを検証する。既存データを退避し、全データと新世代を原子的に反映する。途中失敗なら元の状態を保つ。
- 既存バックアップと旧形式の価格を読み込める。CSVは集計用とし、完全復元には使わない。
- アプリ更新は営業後、入力中・保留の解消とバックアップ確認後に行う。

ブラウザデータ削除・PC故障で記録が失われる可能性があります。永続ストレージの要求やstrict書き込み指定だけで、停電・媒体故障への耐久性を保証しません。

## 7. 非機能要件と受入条件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-01 | 操作性 | 会計と待ち一覧を同時に確認し、別注文の受け渡しで入力中の注文を変えない |
| NFR-02 | 対応環境 | 使用するPC・ブラウザを明示し、実機で準備・保存・復旧を検証する |
| NFR-03 | 保守性 | 画面・業務ルール・アプリケーション・保存を分け、依存を内側へ向ける |
| NFR-04 | 運用性 | 開発者不在で営業前確認・閉店・バックアップ・復元を行える |
| NFR-05 | 整合性 | 連打・並行実行でも二重売上・札重複を防ぐ |
| NFR-06 | データ保護 | PCとブラウザの利用者を限定し、実際の注文・経費・バックアップを公開リポジトリへ入れない |
| NFR-07 | 継続利用 | 開催回・営業日・当時の商品と価格を保持する |
| NFR-08 | 費用 | 営業中に有料サービスやクラウドDBの使用量枠を必要としない |
| NFR-09 | 業務継続 | 模擬営業で会計と受け渡しの配置・操作を確認する |
| NFR-10 | オフライン | 通信なしで再読み込み・ブラウザ再起動後も営業できる |
| NFR-11 | 復旧 | 保存失敗・更新・PC変更時にバックアップと照合から復帰できる |
| NFR-12 | 業務ログ | 会計・取消・受け渡し・完了取り消し・設定変更を追記型の記録へ残す |
| NFR-13 | 保存完了 | 関連データを一括保存し、コミット済みの状態を表示する |
| NFR-14 | 耐久性 | 明示した異常終了・再起動の試験条件で、保存完了記録の欠落0を採用基準とする。未試験の条件を明記する |
| NFR-15 | 結果照合 | 保存成功・失敗・結果不明を区別し、同じIDで照合できる |
| NFR-16 | 復元整合性 | 退避後の変更を検出し、全ストアと世代を一括で置き換える |
| NFR-17 | 保存時検証 | 画面の操作抑止だけに頼らず、ID・価格・金額・札の所有者・状態を保存時に検証する |
| NFR-18 | 再開時保護 | DB消失を自動初期化せず、保存状態を確認して再開する |

操作部品は共通化し、標準の高さを40px、フォーカス枠を一つにします。アイコンだけの操作にも名前を付け、キーボードで選択欄やダイアログを操作できるようにします。

画面の文字サイズは12px・16px・24pxの3種類に統一します。繰り返し表示する操作は意味が分かるアイコンを優先し、会計・返金・札回収の判断に必要な文字は残します。

受け渡し完了の直後に次の札が同じ操作位置へ移動しないようにし、二度押しで別の注文を完了させません。履歴と返金では会計番号・日時・預かり金・お釣りを確認でき、再利用する札だけを注文の識別に使いません。1280×640pxのPC画面でも合計と会計の主操作を確認できる配置にします。注文クリアは新しい入力の開始前なら元に戻せます。

## 8. 本番前に決めること

| 項目 | 確認内容 |
|---|---|
| 端末と担当 | PC・ブラウザ・準備確認担当・会計と受け渡しの操作担当 |
| 営業条件 | 営業時間・販売予定本数・焼き置きや包装・会計場所 |
| 札 | 枚数・満札・紛失・部分受け渡しの扱い |
| 現金 | 取消・返金の現場判断、現金以外の支払いの要否 |
| 経費 | 実際の費目を集計する担当と更新のタイミング |
| バックアップ | 出力頻度・別媒体・保管担当・PC引き継ぎ時の確認方法 |
| 障害 | 許容できる記録損失・紙営業の可否・保存失敗時に営業を止める手順 |

自動試験とは別に、実担当者による模擬営業と、本番PCでのオフライン起動・異常終了・別媒体からの復元を行います。注文件数は未確定のため、1,000件・3,000件は照合用の仮条件です。販売予測や性能の合否基準には使いません。

## 履歴検索と画面整理の追加要件（2026-11-01）

- 営業日・札番号・未受け渡し・注文時刻の範囲を組み合わせて検索できる。
- 時刻は日本時間の分単位とし、時刻・札番号・会計額で昇順／降順に並べ替えられる。検索・並べ替えは保存済み注文を書き換えない。
- 商品価格を縦に揃え、履歴の会計番号を独立列で表示する。通常は現在の営業日を表示し、同じ日付を各行へ繰り返さない。
- 設定の日付・札枚数は編集時だけ共通の保存操作を表示する。
