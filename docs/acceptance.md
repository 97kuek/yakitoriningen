# 初期版の検証範囲

自動試験を通っても、利用するPCでの耐久性や現場運用の検証を代替しません。

## 自動試験

`npm test` はfake-indexeddbを使い、価格計算、保留・確定・札回収・受け渡し・全額取消、同一ID再試行、異内容拒否、並行割当、価格・営業日変更、経費の再試行と翌日引継ぎ、未登録・0円・赤字の区別、売上・返金・本数の集計、書込失敗、JSON検証、整合した出力、復元の原子性・世代を検証します。

`npm run test:e2e` はビルド後のPWAをPlaywright付属Chromiumで操作し、実IndexedDBの保存・再起動、価格変更、オフライン再読み込み、JSON出力・読み直し・復元、実トランザクションの`strict`指定、画面幅390px、二重起動、取消の手順、金額欄の二重枠、設定の項目切り替えと入力保持、経費登録から利益・グラフ表示までを検証します。テストにはサンプルデータだけを使用します。

IndexedDBの耐久性はDexieの`chromeTransactionDurability: 'strict'`、画面は`cache: 'disabled'`とコミット済み結果の購読を使います。設定の根拠は[Dexie公式ドキュメント](https://dexie.org/docs/Dexie/Dexie)です。strictの指定は停電に対する無条件の保証ではありません。

## 本番PCで行うこと（未検証）

- [ ] OS・機種・ブラウザ・バージョンを記録する。
- [ ] オンライン準備後、通信なしでブラウザを閉じ、同じURLから起動する。
- [ ] 保存完了の表示後、ブラウザを終了・再起動し、件数・金額・注文・札・ログを照合する。
- [ ] 保留保存後、確定直前・直後・画面反映前でアプリを停止し、同じIDの照合から重複なく復帰する。
- [ ] 保存容量不足・復元途中停止で旧状態か完全な復元状態を保持する。
- [ ] OS異常終了・停電について、試験条件・保存完了記録・復帰後記録を比較する。対象条件で欠落0を合格条件にし、欠落した場合は本番利用へ進めない。試験できない条件は未検証として残す。
- [ ] 1,000件・3,000件を仮条件に保存と出力・復元を確認する。性能は合否基準にせず、件数・金額・札・ログの一致を確認する。
- [ ] 実際に別媒体へJSONを退避し、別ブラウザまたは別PCで復元する。
- [ ] 実担当者が開発者の操作なしで、営業開始・通常会計・保留照合・取消・バックアップ・復元を行う。
- [ ] 満札・札紛失・部分受け渡し・紙営業・許容損失・バックアップの頻度・保存先・担当を責任者と合意する。

## 配布

`firebase.json`に静的配信の設定のみ用意しています。Firebaseプロジェクトの作成、課金設定、実際のデプロイは行っていません。公開する場合はHTTPSの同じオリジンを継続利用してください。別オリジンにはDBが自動で移りません。
