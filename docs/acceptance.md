# 検証範囲

更新日：2026-11-02。自動試験を通っても、本番PCの耐久性や実際の担当者による運用確認を代替しません。コマンドは[CONTRIBUTING](../CONTRIBUTING.md)を参照してください。件数は固定せず、試験対象の挙動で範囲を管理します。

## 自動試験

| 対象 | 確認する内容 |
|---|---|
| 単体・保存 | 価格・セット・旧価格、注文状態、同じ操作IDの再試行、異内容・古い世代の拒否、札の重複・再利用、原子的な書き込みと失敗時の巻き戻し |
| JSON・CSV | 新旧バックアップの検証、日別抽出・他の日を保持する復元、会計番号衝突・プレビュー後変更の拒否、日本語と日本時間のCSV、履歴検証の操作順 |
| 営業日・在庫・集計 | 初日12枚→別日30枚→初日再開、日別経費・在庫の保持、予約分を超える在庫減少の拒否、返金で在庫を戻さないこと、売上・本数・利益・待ち時間 |
| ホーム・開始 | 初回の明示的な準備、途中会計の再開、ロゴと中央ホームからの遷移、入力保持、別日の準備・保存済み日の再開、営業を始めず集計できること |
| 会計・現金 | 1〜9キーとEnter、長押し・二度押し防止、＋金額・ちょうど・手入力、上限・不正入力、お釣りと確定の位置、札確認の選択・保存失敗・再試行 |
| 札回収・返金 | 回収後の一覧除去と取消、次の札への誤操作防止、札再利用後の取消拒否、返金後の未回収札、保存失敗時の所有権保持 |
| 履歴・設定 | 時間帯・札番号・状態・ソート・ページング、行クリックとキーボードの詳細表示、返金との分離、CSV全ページ出力、整数入力、空欄と0、未保存編集の保護 |
| 終了 | 未回収札・途中会計・未保存編集の拒否、当日JSONと全件CSVの出力、保存後変更の検出、利用者による保存確認、ホームへの復帰 |
| 更新・容量 | オフライン再起動、更新検出と入力中の適用抑止、同日復元後の経費反映、90%容量警告と再通知条件、会計入力に割り込まないこと |
| 配置 | 3種類の文字サイズ、390pxの会計操作、1280×640pxの主操作、30商品のスクロール、開閉時の位置、営業日選択の可読幅、返金文字の枠内表示 |

単体試験はVitest・fake-indexeddbを使います。ブラウザ試験はビルドしたPWAをPlaywright付属Chromiumで開き、専用ポート4273と架空データだけを使用します。利用者の本番DBを初期化・更新しません。

オフライン試験はService Workerの準備完了後に記録を読み込み、再読み込みしてから通信を切ります。二重起動の試験は2画面を使い、操作権がない側を止めます。履歴・配置だけでなく、実IndexedDBの保存・再起動も試験します。

在庫の追加・廃棄差分（旧`adjustStock`）も互換性試験に残します。現在の画面に調整ダイアログがあるという意味ではありません。現行UIは在庫数の直接入力です。

## CI・公開で確認すること

GitHub Actionsは型・単体試験・整形・ビルド・ブラウザ試験に成功した成果物だけを公開します。PRは検証だけ、mainのpushまたはmain上の手動実行は公開も行います。公開直前に最新mainとの一致を確認し、古い実行を公開しません。

公開後はHTMLが最新のJS・CSSを指し、配信内容が検証済みビルドと一致することを確認します。設定と手順は[公開と更新](deployment.md)を参照してください。

## 本番PCで確認すること（自動試験の範囲外）

- [ ] OS・機種・ブラウザ・バージョンと使用URLを記録する。
- [ ] オンライン準備後、通信なしでブラウザを閉じ、同じURLから起動する。
- [ ] 保存完了後の終了・再起動で件数・金額・注文・札・ログが一致することを確認する。
- [ ] 確定直前・直後や保留保存後の強制終了から、二重入金せず照合して復帰する。
- [ ] 容量不足・復元中停止で、元の状態か完全な復元状態のいずれかを保持する。
- [ ] 停電・OS異常終了は条件を記録して検証する。対象条件で保存完了記録の欠落0を採用基準とし、未試験条件を残す。
- [ ] 1,000件・3,000件は照合用の仮条件として保存・出力・復元を確認する。販売予測や全端末の速度保証には使わない。
- [ ] JSONとCSVの両方を保存できること、複数ダウンロードの確認、別媒体への退避と別ブラウザでのJSON復元を確認する。
- [ ] 実担当者が開発者の操作なしで、準備・会計・修正・札回収・取消・設定・履歴・返金・閉店・集計・復元を行う。
- [ ] 営業時間・販売予定・満札・紛失・部分受け渡し・紙営業・許容損失・バックアップ担当と保管先を責任者と決める。

`strict`なIndexedDB書き込みや記録保護の要求は、PC故障・停電・手動削除への無条件の保証ではありません。性能測定の条件と限界は[性能確認](performance.md)を参照してください。
